# Skillbas Development Notes

## Purpose

`skillbas` is a pi extension for running small Skill BASIC programs inside pi. It exists to experiment with replacing prompt-only skills with Skill BASIC programs that can compute, branch, read simple input, and emit prompt text through `PROMPT`.

The extension is implemented in:

```text
.pi/extensions/skillbasic.ts
```

## TypeScript Interpreter

The extension includes a small TypeScript Skill BASIC interpreter. It intentionally does not call the Rust interpreter or Ollama.

Supported statements:

- `REM`
- `PRINT` and `?`
- `INPUT`
- `LET` and bare assignment such as `A = 1`
- `IF ... THEN ...`
- `GOTO`
- `PROMPT`
- `END`
- `STOP`

Supported expression features:

- Numbers
- Strings
- Numeric variables
- String variables ending in `$`
- `+`, `-`, `*`, `/`
- Comparisons: `=`, `<>`, `<`, `>`, `<=`, `>=`
- Parentheses

`PROMPT <expr>` evaluates the expression, appends the result to `result.prompts`, and also writes `[PROMPT] ...` to stdout.

## `skillbas` Tool

The extension registers an LLM-callable tool named `skillbas`.

The tool can run:

- Inline code via `code`
- Project-local files via `path`

Accepted file extensions:

- `.bas`
- `.sbas`
- `.skillbas`

The tool returns:

- Instruction count
- Collected `PROMPT` outputs
- stdout
- stderr
- final variables in structured details

Important: `skillbas` tool results are returned as tool context. The tool does not call `pi.sendUserMessage()`.

## Prompt Handling

Early experiments tried to implement chatbot behavior as an LLM-callable tool that called `pi.sendUserMessage()` from inside tool execution. That caused a loop:

```text
model calls tool
tool sends user message
new turn starts
model calls tool again
...
```

The lesson is:

- LLM-callable tools should return results.
- Extension commands may call `pi.sendUserMessage()`.
- Do not call `pi.sendUserMessage()` from a tool that the model can decide to call again.

## `/skillbas:<name>` Commands

The extension scans project-local Skill BASIC skill files from:

```text
.pi/skillbas/
```

Files with `.sbas` are treated as Skill BASIC prompt skills:

```text
.pi/skillbas/aichatbot.sbas -> /skillbas:aichatbot
```

`.skillbas` is still accepted as a compatibility alias, but `.sbas` is the preferred extension.

Command names are derived from file stems and must match:

```text
lowercase letters, numbers, and hyphens
```

Examples:

```text
aichatbot.sbas       -> /skillbas:aichatbot
review-note.sbas     -> /skillbas:review-note
summarize-code.sbas  -> /skillbas:summarize-code
```

## `.sbas` File Format

A `.sbas` file is a Skill BASIC program. The first `REM` line is used as the command description when available.

Example:

```basic
5 REM AI chatbot
10 INPUT "YOU: "; Q$
20 PROMPT Q$
30 GOTO 10
```

Command arguments are passed to the interpreter as one stdin line:

```text
/skillbas:aichatbot hello
```

becomes:

```text
stdin = "hello\n"
```

## Command Execution Flow

When `/skillbas:name args` runs:

1. The command handler reads `.pi/skillbas/name.sbas`.
2. It runs the TypeScript interpreter.
3. Arguments are supplied as stdin.
4. Execution stops after the first `PROMPT`.
5. The collected prompt is wrapped in a skill-style block.
6. The block is sent to pi with `pi.sendUserMessage()`.

The first-prompt stop is intentional. It prevents programs like `aichatbot.sbas`, which contain `GOTO` loops, from running until timeout.

## Skill-Style Message Format

Generated prompts are sent as user messages in a block like:

```text
<skill name="skillbas:aichatbot" location=".pi/skillbas/aichatbot.sbas">
References are relative to .pi/skillbas.

hello
</skill>
```

This mirrors pi's built-in `/skill:name` expansion pattern while allowing the skill body to be generated by Skill BASIC.

## Active Tool Behavior

Only the `skillbas` interpreter tool is added to active tools during `session_start`.

`/skillbas:<name>` commands are extension commands, not LLM-callable tools. They are not added to active tools.

This separation avoids automatic tool-call loops.

## Current Example Files

Current project-local examples:

```text
.pi/skillbas/aichatbot.sbas
.pi/skillbas/hello.sbas
```

Usage:

```text
/reload
/skillbas:aichatbot hello
```

Expected behavior:

1. `hello` is read into `Q$`.
2. `PROMPT Q$` emits `hello`.
3. pi receives the generated skill-style user message.
4. No LLM tool-call loop occurs.

## Known Limitations

- The TypeScript interpreter is intentionally small and does not implement full Skill BASIC.
- `INPUT` currently receives command arguments as a single stdin line.
- `/skillbas:<name>` commands are discovered when the extension loads. Add or rename `.sbas` files, then run `/reload`.
- `.sbas` commands stop after the first `PROMPT`.
- The implementation currently scans `.pi/skillbas` under `process.cwd()` during extension load.

## Future Work

- Add richer stdin handling for multi-input programs.
- Add frontmatter-like metadata support if `REM` descriptions become too limited.
- Add better command discovery diagnostics.
- Consider exposing command output or interpreter variables in the generated skill block.
- Decide whether `.skillbas` compatibility should be removed after `.sbas` is established.
